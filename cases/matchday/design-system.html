System01

3계층 아키텍처

벤치마크 대상 7개 시스템(Spectrum · Material · Fluent 2 · Carbon · Polaris · shadcn · Ant)의 공통 처방은 하나다 — primitive → semantic → component 3계층을 명시적으로 분리할 것. 계층이 암묵적인 2계층 시스템과 종합 점수(4.5 vs 3.1)가 갈렸다.

TIER 177 tokens

Primitives

tokens/primitives.css

원시 값. 그린 · 차콜 · 상태 팔레트, 타입 스케일, 4-베이스 간격, 반경, elevation, 모션. 테마가 바뀌어도 이 파일의 값은 변하지 않는다.

계약: 리터럴만 정의. 누구도 이 계층을 직접 소비하지 않는다 — 단, Tier 2의 매핑 제외.
TIER 2115 tokens

Semantic

tokens/semantic.css

역할 앨리어스. --bg-card, --text-muted, --line. dark/light 테마 매핑은 오직 이 파일에서만 일어난다 — neutral 래더는 값이 아니라 역할이 뒤집힌다.

계약: Tier 1만 참조. 테마 분기의 유일한 소유지.
TIER 3176 tokens

Component

tokens/component-tokens.css

컴포넌트별 앨리어스. --button-bg-primary-hover, --player-bg-selected. 셀렉터 수술 없이 변수 몇 개로 컴포넌트를 리스킨한다.

계약: Tier 2 참조가 원칙, 앨리어스가 없을 때만 Tier 1. 테마 코드 0줄.

왜 3계층인가 — 벤치마크의 결론

Spectrum · 종합 4.5/5 — 1위

3단계 fallback 체인. var(--highcontrast-*, var(--mod-*, var(--spectrum-*))) — 536개 오버라이드 훅, 하드코딩 19건은 전부 리셋 값. 소비자 오버라이드가 스펙에 포함된다.

Ant Design · Seed → Map → Alias

단일 입력 팔레트 파생. colorPrimary 씨앗 하나로 10단계 팔레트와 hover/active/bg/border가 자동 파생된다. 값의 중복 정의가 없다.

Polaris · "가장 우아한 패턴"

Custom Property 상태 머신. variant 클래스가 CSS 선언 없이 변수만 재할당해 조합 폭발을 O(n+m)으로 해결한다. specificity 전쟁이 없다.

파일 구조

design-tokens/ ├── spotify.css ← 호환 번들 (@import 4개) — 기존 화면 29 + 갤러리는 그대로 동작 ├── components.css ← 클래스 계층 (Tier 2·3만 소비) └── tokens/ ├── primitives.css TIER 1 원시 값 · 테마 불변 ├── semantic.css TIER 2 역할 앨리어스 · dark/light 매핑 └── component-tokens.css TIER 3 컴포넌트 토큰 · 오버라이드 훅

라이브 증명 — 스코프 오버라이드 훅

팔레트를 누르면 이 블록의 스코프에 토큰이 덮어씌워진다 — 클래스는 그대로, 컴포넌트만 바뀐다. 이퀄라이저처럼 var(--brand)를 직접 쓰는 요소는 브랜드 색 하나로 따라오고, 버튼 · 체크 · 토글 · 슬라이더 · 탭은 각자의 컴포넌트 토큰(--button-bg-primary 등)을 통해 따라온다. 오버라이드 경로가 계층대로 작동하는, 눈으로 보는 증거.

System02

        
네이밍 규칙

        

          이름이 규칙을 어기면 토큰 검색도, Figma 매핑도, 자동화도 무너진다.
          계층마다 하나의 패턴만 쓴다 — kebab-case로 통일.
        


        

          --buttoncomponent-bgproperty-primaryvariant-hoverstate
        


        

          
R1Tier 1 — {hue}-{step} · {scale}-{step}. 예: --green-500, --space-4, --fs-title-2.

          
R2Tier 2 — {category}-{role}[-{state}]. 예: --bg-card-hover, --text-muted, --line-strong.

          
R3Tier 3 — {component}-{property}-{variant}-{state}. 예: --cardbtn-bg-red-on. variant/state는 필요할 때만 붙인다.

          
R4fg/bg 쌍. 배경 토큰이 있으면 그 위 잉크 토큰을 반드시 함께 정의한다 (--badge-bg-live ↔ --badge-fg-live) — 대비를 토큰 수준에서 보증.

          
R5하향 참조만. 클래스는 Tier 3·2만, Tier 3는 Tier 2(원칙)·1(예외)만. 상향 참조 금지.

          
R6이름 = 계약. 토큰명 변경은 breaking change. 비추천은 새 이름 추가 + 주석, 삭제는 다음 메이저에서.

그린은 소중하다 — Do / Don't

        
Spotify 언어의 핵심 규율: 그린은 오직 주요 액션 · 활성 · 라이브에만. 나머지는 회색조가 책임진다.

        

          

            
✓

            
DO — 주요 액션 하나한 화면에서 그린 버튼은 하나. 시선이 갈 곳이 명확하다.

          

          

            
✓
              LIVE
            

            
DO — 라이브 · 활성 신호작은 닷과 이퀄라이저. 그린은 상태 신호일 때 가장 강하다.

          

          

            
✓
              

            

            
DO — 데이터는 단색으로점유율 바는 화이트/그레이. 색은 콘텐츠(엠블럼)가 가져간다.

          

          

            
✕
              

            

            
DON'T — 장식 그라디언트크롬에 색을 칠하지 않는다. 무지개는 스포티파이가 아니다.

          

          

            
✕
              

                
              

            

            
DON'T — 시리즈마다 새 색차트는 잉크 계층으로. 의미 있는 단일 지표만 상태색을 쓴다.

          

          

            
✕
              그린 제목 텍스트
            

            
DON'T — 그린 본문 · 제목그린 텍스트는 --text-brand 상태 표시 전용. 제목은 잉크 계층으로.

Operations11

        
테마 — 역할 반전

        

          라이트 테마는 값을 바꾸는 게 아니라 역할을 뒤집는다 —
          neutral 래더의 낮은 칸이 잉크가 되고 높은 칸이 표면이 된다.
          그래서 컴포넌트 계층과 클래스 계층에는 테마 코드가 0줄이다.
          우측 상단 "테마 전환"으로 지금 이 문서를 통째로 뒤집어보라.
        


        

          

            
Dark — 기본

            
--neutral-1000#000000 · 크롬

            
--neutral-950#121212 · 기본 배경

            
--neutral-925#191919 · raised

            
--neutral-900#1D1D1D · 카드

            
--neutral-850#2A2A2A · hover

            
--neutral-400#B3B3B3 · 보조 잉크

            
--neutral-0#FFFFFF · 제목 잉크

          

          

            
Light — 역할 반전

            
--neutral-1000#F2F2F2 · 크롬

            
--neutral-950#FFFFFF · 기본 배경

            
--neutral-925#FAFAFA · raised

            
--neutral-900#F6F6F6 · 카드

            
--neutral-850#EFEFEF · hover

            
--neutral-400#5E5E5E · 보조 잉크

            
--neutral-0#000000 · 제목 잉크

          

        


        

          

            
같은 마크업, 같은 클래스, 다른 테마

            
아래 컴포넌트들은 테마별 CSS가 없다 — 전부 var() 체인으로 반전된다.

          

          
        

      


      
      

        
Operations12

        
거버넌스 — 벤치마크에서 가져온 것, 다음에 할 것

        

          7개 시스템 벤치마크의 처방 중 이번 v3.0에 적용한 것과,
          업계 공통 미해결 과제(Figma 동기화)에 대한 실용적 접근 계획.
        


        

          
벤치마크 교훈Encore v3.0 적용

          
            
primitive → semantic → component 3계층 분리 (Spectrum · Material · Carbon · Ant 공통 처방)tokens/ 3파일 + components.css 물리 분리. 각 파일 헤더에 계층 계약 명시.

            
토큰 네이밍 패턴 통일 — "{category}-{property}-{role}-{state}" (Polaris · Spectrum)Tier 3 전체에 적용. R1–R6 규칙 문서화. kebab-case 단일 컨벤션.

            
모든 디자인 값 var() 소비 — hardcoded 제거 (전 시스템 공통)클래스 계층의 원시 색상 직접 참조 0건 (스크린샷 픽셀 동등성 검증 완료).

            
오버라이드 훅 — Spectrum의 --mod-* 536개--mod-* 2단계 fallback 패턴 문서화. 스코프 변수로 리스킨.

            
토큰별 description (Polaris 모범 사례)토큰 파일 인라인 주석 + 이 쇼케이스의 시각 레퍼런스 (스와치 · 타이포 샘플).

            
fg/bg 쌍 — 대비를 토큰 수준에서 보증 (Polaris · shadcn)badge · button · snackbar 등 상태 컴포넌트 전부에 -fg/-bg 쌍 정의.

            
테마 전환은 앨리어스 계층에서만 (전 시스템 공통)라이트 테마 = semantic.css의 역할 재매핑. Tier 3 · 클래스는 테마 코드 0줄.

            
"토큰 수 ≠ 품질" — Material 1,700개도 maintenance mode368개로 절제. 표시형 도메인 컴포넌트는 Tier 2 직접 소비를 허용하는 명시적 정책.
