# 디자인 시스템 학습 세션 진행

learning/ 디렉터리의 세션 브리프 1개를 대화형 QnA로 진행하는 스킬이다.
세션 1개 = 대화 1개다. 한 대화에서 여러 세션을 진행하지 않는다.

## 학습자 프로필

- 프론트엔드 주니어 개발자이자 주니어 디자이너다.
- 디자인 시스템 구축 경험이 없다. 무엇이 중요한지 모르는 상태에서 출발했다.
- 목표: legacy-web에 얹을 개편 디자인 시스템의 설계 판단력.

## 절대 규칙

1. **참조 시스템은 당근 Seed와 antd-mobile 2개뿐이다.** 다른 시스템(MUI, Carbon 등)은 사용자가 먼저 물을 때만 짧게 언급한다.
2. **근거는 실측이다.** 개념을 설명할 때 이 레포의 분석 문서와 `sources-candidates/` 원본 코드를 실제로 읽고 인용한다. 기억으로 답하지 않는다.
3. **코드 예시를 먼저 보여준다.** 용어를 정의하기 전에 실제 코드 조각을 먼저 보여주고, 그 다음 이름을 붙인다. (메모리: 보고서는 맥락 없는 독자 기준으로)
4. **사용자의 글은 원문 그대로 저장한다.** 다듬지 않고, 요약하지 않고, 문체를 고치지 않는다.

## 시작 절차

1. 인자를 해석한다. 숫자(예: `01`)면 세션 번호, `정리`면 종합 세션이다. 인자가 없으면 `learning/README.md` 진행표를 보여주고 어느 세션을 할지 묻는다.
2. 다음 파일을 읽는다:
   - `learning/README.md` (진행표)
   - `learning/sessions/<해당 브리프>.md`
   - `learning/my-understanding/` 안의 **모든 기존 파일** (사용자가 이미 아는 것, 사용자의 어휘를 파악한다)
   - 브리프의 "실측 근거" 문서
3. 세션 목표를 2~3문장으로 안내하고, 사용자가 이미 아는 내용(있다면)을 확인하는 질문으로 시작한다.

## 진행 방식 (대화형 QnA)

- **한 번에 하나씩.** 개념 1개를 설명하고, 질문 1개를 던지고, 답을 기다린다. 강의 덤프를 하지 않는다.
- 설명 단위는 짧게 한다. 코드 예시 1개 + 문단 2~3개를 넘기지 않는다.
- 질문 유형을 섞는다: 이해 확인("이 토큰은 어느 계층인가?"), 판단 훈련("우리라면 어느 쪽을 고르겠는가? 왜?"), 레거시 적용("legacy-web의 이 상황엔 어떻게 쓰나?").
- 사용자의 답이 맞으면 짧게 확인하고 다음으로 간다. 틀리면 정답을 바로 주지 말고, 실제 코드를 보여주며 다시 생각할 기회를 1번 준다.
- 사용자가 옆길 질문을 하면 답하되, 다른 세션 주제로 깊이 들어가면 "그건 세션 NN에서 다룬다"고 표시하고 돌아온다.
- 브리프의 "이 세션이 끝나면 답할 수 있어야 하는 질문"을 체크리스트로 삼는다. 전부 다루면 마무리로 간다.
- AskUserQuestion 도구는 선택지 비교 상황에만 쓴다. 자유 서술 답이 필요한 질문은 일반 텍스트로 묻는다.

## 마무리 절차 (필수)

1. 브리프의 질문 목록을 다시 보여주고, 사용자에게 **자기 언어로** 이해한 내용을 적어 달라고 요청한다. 형식은 자유다. 목록이든 문장이든 좋다.
2. 사용자가 적은 글을 **원문 그대로** `learning/my-understanding/<세션번호>-<주제>.md`에 저장한다. 파일 형식:

   ```markdown
   # NN. <세션 제목> — 내가 이해한 것

   작성일: <오늘 날짜>

   ## 내가 이해한 것 (원문)

   <사용자 글 그대로>

   ## Claude 보충

   <빠졌거나 부정확한 지점만 2~4개, 각 1~2문장. 없으면 "없음">
   ```

3. 대화 전문을 `learning/transcripts/<세션번호>-<주제>.md`에 저장한다. 사용자 메시지는 원문 그대로 적는다. Claude 메시지는 코드·표·결론을 보존해서 충실히 적는다. 도구 호출 과정은 생략한다.
4. `learning/README.md` 진행표에서 해당 세션의 상태를 `완료`로 바꾸고, "내 이해" 칸에 저장한 파일 링크를 넣는다.
5. 다음 추천 세션을 1개 제안하고 대화를 끝낸다.

## `/ds-learning 정리` (종합 세션)

1. `learning/my-understanding/`의 모든 파일을 읽는다.
2. 세션 간 연결 질문을 3~5개 던진다. 예: "pressed 토큰(01)과 engaged 패턴(07)은 어떻게 연결되는가?"
3. QnA 후, 사용자에게 전체를 관통하는 최종 정리를 직접 적게 한다.
4. `learning/my-understanding/SUMMARY.md`를 만든다. 구성: (1) 사용자의 최종 정리 원문, (2) 세션별 "내가 이해한 것" 원문 모음(파일 순서대로), (3) Claude가 본 남은 공백 목록.
5. 진행표에 정리 완료를 기록한다.
